На моїй системі: 16 логічних ядер (8 фізичних)запуск 16 потоків для обчислювальної задачі дав прискорення лише 
**0.99** (мінімальний час склав 6.18 с проти 6.14 с у послідовному виконанні).

Відношення процесорного часу до настінного для 8 потоків склало точно **1.0**, 
що свідчить про те, що незважаючи на наявність 8 активних потоків, у кожен момент часу реально працювало лише одне ядро процесора.

Обчислення взагалі не прискорилися через наявність у CPython механізму **GIL (Global Interpreter Lock)** — глобального блокування інтерпретатора, 
яке дозволяє виконувати байт-код Python одночасно лише одному потоку.

Натомість задача з очікуванням прискорилася практично лінійно (на 16 потоках — **×16.0**, а на 32 потоках — **×31.7**),
оскільки під час очікування ввід-виводу (`time.sleep`) потік добровільно звільняє GIL, дозволяючи іншим потокам працювати паралельно.

Для прискорення своєї обчислювальної задачі (Мандельброта) я оберу мультипроцесовість (`multiprocessing`), оскільки вона створює окремі процеси з власними інтерпретаторами Python та незалежними GIL, 
а потоки для CPU-bound задач у Python непридатні.
